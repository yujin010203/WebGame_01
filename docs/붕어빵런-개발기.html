1 · 기획

무엇을 만들 것인가

"크롬 공룡 게임 같은 걸 만들고 싶다"에서 출발했습니다. 핵심은 배우기 5초, 마스터는 어려운 원-버튼 러너. 여기에 붕어빵이라는 한국적 소재와 수집·완성 메커니즘을 얹어 차별점을 만들었습니다.

Concept

원-버튼 엔들리스 러너

점프 하나로 모든 걸 하는 횡스크롤 러너. 시간이 지날수록 빨라져 자연스럽게 난이도가 오르고, "한 판 더"를 부르는 즉시 재시작 루프를 목표로 했습니다.

Hook

피하기 + 모으기 + 완성

단순 회피에 수집 요소를 더했습니다. 붕어빵 조각을 모아 팥붕어빵(보너스 점수)이나 슈크림붕어빵(무적)을 완성 — 위험을 감수하고 조각을 먹을지 판단하게 만드는 리스크·리워드.

Identity

코드로 그린 픽셀아트

에셋 파이프라인 없이 시작하려고 스프라이트를 전부 js/sprites.js의 오프스크린 캔버스에 코드로 그렸습니다. 파스텔 오락실 톤으로 통일.

Scope

정적 사이트, 의존성 0

빌드 스텝·프레임워크 없이 index.html만 열면 도는 순수 정적 사이트. 온라인 랭킹만 선택적으로 Firebase에 연결 — 없으면 로컬 랭킹으로 폴백.

설계 결정은 구현 전에 문서로 합의했습니다 — docs/superpowers/specs/ 아래 스프라이트 크기·무적 이펙트·PNG 교체 설계안이 그 기록입니다.

2 · 게임 규칙

어떻게 노는가

모든 규칙은 js/game.js 상단 상수로 명시됩니다. 최종 점수 = 달린 거리(1m = 1점) + 붕어빵 점수.

Space / ↑ / W / 탭 점프. 공중에서 한 번 더 누르면 2단 점프 — 장애물 스폰 간격은 2단 점프로 넘을 수 있는 최소치를 보장합니다.
🚧 충돌 하트 −1, 1.5초 무적. 하트 3개가 모두 소진되면 게임 오버.
🍞 붕어빵 조각 +100점. 대부분 1개씩, 가끔 2개가 지면 또는 점프 높이에 스폰됩니다.
팥 × 5 팥붕어빵 완성 — +500점 보너스.
슈크림 × 5 슈크림붕어빵 완성 — 5초 무적. 무적 중엔 장애물을 부수며 통과합니다.
🏆 랭킹 같은 닉네임은 최고 점수 한 줄만 랭킹에 오릅니다(중복 제거).

4 · 구현 하이라이트

핵심 시스템

고정 프레임이 아닌 dt 기반 루프라 기기·프레임레이트가 달라도 체감 속도가 일정합니다.

Loop

델타타임 게임 루프

매 프레임 경과 시간(dt)으로 이동·거리·가속을 계산합니다. 탭 비활성 등으로 dt가 튀면 0.05초로 클램프해 순간이동을 막습니다.

// 속도는 매초 가속, 상한에서 포화
speed = Math.min(SPEED_MAX, speed + ACCEL*dt);
distance += (speed*dt) / PX_PER_M; // 20px = 1m
Difficulty

자기조정 난이도

장애물 간격을 현재 속도에 반비례로 좁히되, 0.55초 하한을 둬서 아무리 빨라도 2단 점프로 넘을 수 있는 최소 간격을 보장합니다. 붕어빵은 2.2~4.8초로 드물게.

Collision

AABB 충돌 + 무적 분기

사각형 겹침(AABB)으로 판정. 슈크림 무적 중이면 장애물을 부수고, 피격 무적(iframe) 중이면 무시하며, 그 외엔 하트를 깎습니다. 조각은 먹으면 게이지가 차고 5개마다 완성 처리.

Effect

무적 무지개 이펙트

무적 중 고양이에 hue-rotate 필터로 무지개 색조를 돌리고 밝기를 깜빡이며, 주위에 별 파티클을 뿌립니다. 피격 무적의 깜빡임과는 분리해 충돌을 피했습니다.

Assets

PNG 자동 폴백 로더 — 판정을 흔들지 않는 교체

나중에 직접 만든 PNG로 갈아끼울 수 있도록 js/assets.js를 추가했습니다. 핵심 설계는 표시 크기·히트박스를 코드가 정한 native 치수로 고정하는 것 — PNG 픽셀 크기가 달라도 게임 판정은 그대로입니다. 배경·바닥은 캔버스 타일로, 하트·버튼은 <body>에 클래스를 붙여 CSS 배경 이미지로 교체합니다. PNG가 없으면 지금처럼 코드 그림을 씁니다.

5 · 트러블슈팅

부딪힌 문제와 해결

이 환경(Windows + git 자동 줄바꿈 + 정적 게임)에서 반복적으로 발목을 잡은 함정들. 증상만 보면 코드 버그로 오진하기 쉬운 것들이라 원인 규명이 관건이었습니다.

CRLF ↔ LF 편집 실패

증상merge/checkout 후 편집 도구의 문자열 매칭이 계속 실패
원인.gitattributes: * text=auto로 작업 트리 파일이 CRLF가 되어 LF 기준 매칭과 어긋남
해결편집 전 sed -i 's/\r$//'로 LF 정규화 후 편집. 커밋 시 다시 LF로 정규화되어 기능 영향 없음

브라우저 캐시 오진

증상JS/CSS를 고쳐도 브라우저가 옛 파일을 써서 "코드가 맞는데 안 되는" 것처럼 보임
원인python -m http.server가 캐시를 허용
해결Cache-Control: no-store를 붙인 커스텀 dev 서버로 항상 최신본을 받게 함

크기 축소 시 히트박스 어긋남

증상스프라이트를 30% 줄이자 판정이 실제 그림과 맞지 않음
원인히트박스 여백이 절대 픽셀값(예: x+14, w-30)이라 겉모습만 작아짐
해결여백도 동일하게 SIZE 0.7배 적용 — 판정 비율 유지, 난이도 체감 동일

하트 PNG 찌그러짐

증상PNG 하트가 이모지 글리프 폭에 눌려 가로로 찌그러짐
원인하트 컨테이너가 이모지 문자 폭을 따라감
해결하트에 정사각 박스를 부여해 이미지 비율을 지킴

브라우저를 직접 띄우기 어려운 환경이라, Edge의 --headless --dump-dom으로 DOM·캔버스 로직(예: canvas.toDataURL)을 헤드리스 검증했습니다.

6 · 배포 & 온라인화

어느 기기서나, 공유되는 랭킹

"다른 기기에서 테스트하고 싶다 + 랭킹을 기기 간에 공유하고 싶다"는 요구에서 GitHub Pages 공개와 Firebase 연결로 이어졌습니다.

Firestore

온라인 실시간 랭킹

rankings 컬렉션에 점수를 저장/조회합니다. 인증 없이 열되 데이터 검증 규칙으로 방어했습니다 — score는 0 이상 정수, 닉네임은 10자 이하. 삭제는 규칙으로 막아 콘솔에서만 수동 삭제됩니다.

match /rankings/{doc} {
  allow read: if true;
  allow write: if score is int && score >= 0
    && nickname is string && nickname.size() <= 10;
}

apiKey는 비밀이 아니라 공개 저장소에 커밋해도 안전합니다. Auth 미사용이라 도메인 허용 설정도 불필요 — 값 하나라도 YOUR_로 남으면 로컬 랭킹으로 폴백.

GitHub Pages

정적 호스팅 공개

저장소를 Public으로 전환하고 main / (root) 브랜치 배포로 켰습니다. Jekyll 처리를 끄려고 루트에 .nojekyll을 커밋했습니다.

라이브 URL —
yujin010203.github.io/WebGame_01
이후 main에 push하면 약 1분 뒤 자동 갱신됩니다.

검토했으나 택하지 않은 대안: LAN 바인딩, 임시 터널(cloudflared).
